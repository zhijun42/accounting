# Accounting

一个为个人生活梳理而设计的本地记账工具。通过关联支付宝、微信、美团和工商银行借记卡的记录，理解每个月实际参与的活动与个人承担的消费。

当前分析目标为 **2026 年 1 月 1 日至 9 月 30 日**。美国银行信用卡消费不纳入本项目。

## 当前状态

本仓库目前提供产品约定和数据库设计，尚未实现应用、导入器或数据库迁移。暂时没有启动命令。

- [数据库 schema spec](docs/schema.md)：表结构、跨平台关联、消费计算、审计和验收案例。
- [.gitignore](.gitignore)：排除个人账单、数据库、导出文件和运行日志。

## 产品约定

- 浏览器访问本机运行的应用，由本地服务读写 SQLite。
- 原始记录保留来源；同一笔消费在订单、支付平台和银行卡中的记录只计算一次。
- 同时保留支付时间和可选的使用日期。使用日期由本人填写；未填写时沿用支付日期，并在 UI 标明默认值。AI 不推断使用日期。
- 支持自定义大类及可选小类，不设置“其他”。信息不足的记录进入待核对队列。
- AI 对每一笔记录检查资金性质和消费分类。依据充分时自动修正，有歧义时交由本人核对；人工确认的分类受到保护。
- 修改分类、使用日期、个人承担金额或关联关系时，持久记录修改前后值、操作者、理由和证据。
- 垫付归还、退款和本人账户之间的资金移动分别处理。个人消费统计使用本人承担的净额。
- 年卡、多次课暂记为单笔，不做按月或按次分摊。
- 日常删除使用可恢复的软删除。永久清除是独立功能，后续实现时另行定义。

## 数据边界

公开仓库仅保存源代码、设计文档和明确编造的测试数据。原始账单、账户信息、SQLite 文件、AI 修改日志、截图、解析中间产物和备份只保留在本机。

建议将后续私有文件放入以下已忽略目录：

```text
data/
  imports/    原始账单
  db/         SQLite 数据库及其附属文件
  exports/    私人报表
  backups/    备份
  work/       PDF 页面、解析中间文件等
```

现有账单不必为了本次文档提交而移动。仓库也按扩展名忽略 CSV、Excel 和 PDF 文件；将来如需提交公开样本，应先制作完全虚构的 fixture，再明确调整相应忽略规则。

`.gitignore` 不会移除已经被 Git 跟踪的文件。每次提交仍须检查暂存区，避免提交个人数据。公开文档和截图中也不应包含真实交易、账户标识或本机私有路径。

提款或充值只能说明资金移动，不能据此还原之后的现金消费；如需纳入现金购买，必须手工补记实际用途和金额。文件日期覆盖完整，也不等于所有记录已经完成关联、分类或核对。

## 后续实现顺序

1. 实现 SQLite 迁移、约束及审计写入协议。
2. 实现 CSV、XLSX、PDF 导入，验证来源合计并处理重复和跨平台关联。
3. 实现逐笔核对、使用日期填写、分类管理和修改历史 UI。
4. 实现按使用日期聚合的月度生活视图。

技术栈和 AI 的运行集成方式将在实现阶段确定。当前设计不要求内置某个模型，也不将本地数据库等同于模型必须离线运行。
